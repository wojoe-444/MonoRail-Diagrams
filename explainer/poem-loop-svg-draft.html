Poem loop

Three separate Codex runs per round, repeated three times, drawn in standard BPMN notation so each shape carries a fixed meaning.

Shapes used

  • Start eventThin circle. Where the process begins.
  • End eventThick circle. Where it stops.
  • Service taskRounded box with a gear. An automated step; here it runs codex exec.
  • Looping sub-processA box of steps with a circular arrow. It repeats.
  • Data storeCylinder. A value that outlives one round.
  • Data objectPage with a folded corner. A value used inside one round.
  • Sequence flowSolid line, filled arrowhead. The order of steps.
  • Message flowDashed, circle at the sender, open arrowhead. A message to another participant.
  • Data associationDotted line. Which step reads or writes a piece of data.
  • PoolBand on the left. A participant whose steps are drawn out.
  • Black-box poolPlain bar. A participant we only talk to; its insides are not drawn.

Reading it

  1. The script starts with a bland seed prompt and enters the Round box, which repeats three times.
  2. In each round the three tasks run left to right. Each one sends a request to Codex (the left dashed line, labelled with what it sends) and waits for the reply (the right dashed line).
  3. Every request is its own codex exec process. The grader receives only GRADER_PROMPT and the poem, so it never sees the prompt that produced it.
  4. Only the reviser changes anything that carries over. It overwrites writer_prompt, and the next round's writer reads it.
  5. The script never touches a login token. Codex reads its own ChatGPT sign-in from ~/.codex.
